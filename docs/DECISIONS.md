## D004 — 文本与忽略规则（2026-11-24）

- 决策：新增文本默认 UTF-8/LF，PowerShell 脚本预设 CRLF；两份原始任务书在 Git 中不进行换行转换。仅这两份任务书允许原有 Markdown 行末空格。
- 原因：本机 Git 的 core.autocrlf=true；原任务书第 3–5 行的两个空格是 Markdown 硬换行，保留原始字节及排版。
- 替代方案：清理原任务书或对所有 Markdown 放宽空白检查；均不采用。
- 影响：.gitattributes 对两份任务书设置 `-text whitespace=-blank-at-eol`；其他文件维持 Git 空白检查。缓存、构建、临时音频、用户数据、密钥和 IDE 私有配置忽略；明确保留测试夹具音频和锁文件。
- 验证：提交前运行 diff 空白检查和代表性 git check-ignore 检查。

## D014 — T05 纯 Rust 音律、模型与内存夹具（2026-11-25）

- 决策：新增零外部依赖的 tuner-core workspace 成员，实现十二平均律、A4 校准、半音/锁定/目标列表映射、只读校验模型和确定性 PCM 生成器；不链接到桌面 crate，不实现 YIN/FFT/设备或 UI 桥接。
- 原因：在无硬件条件下独立验证共享核心；标准库足够完成本任务，无需引入新的包或缓存配置。构造器保护有限值和帧状态，不依赖 UI 替核心兜底。
- 边界：A4 400–480 Hz、容差 0–50 cents；整数 MIDI 0–127，支持升/降号和正确八度。半音/预设等距选高音，1e-10 半音的浮点保护与音准分类保护有记录；目标音分不夹断。
- 契约：草案字段调整为私有验证类型和访问器；Detected 仅一个音高，其他状态无音高，Idle/Error 无信号指标。保留 Vec 形状但 V1 拒绝复音；未加入 serde，T11 再做 Rust/TS/IPC 映射和受校验反序列化。
- 夹具：固定相位正弦/谐波，明确实际采样率、幅度预算和 Nyquist；最多 480,000 样本/32 谐波，纯内存不发声。跨平台末位一致性不承诺。
- 验证：17 核心集成测试与 1 文档测试通过；cargo tree 确认无外部依赖。公式、模型及兼容性约定见 TUNING_CORE，完整工程回归见 TESTING。

## D016 — T06 固定窗口 YIN 参考与可验证范围（2026-11-25）

- 决策：YinConfig 固定 60–300 ms 窗口，默认 300 ms/20–5000 Hz/CMNDF 阈值 0.1/−60 dBFS；按实际采样率计算长度和 lag。最小频率与窗口不相容时拒绝，不静默缩小范围；PCM 正规化、容量及有限值均在分析前校验。
- 实现：去 DC，固定比较段的直接差分/累计归一化，首个合格局部谷，CMNDF 插值谷深选谷/原始差分插值周期；无谷返回 LowConfidence，范围越界返回 NoPitch，不强制全局最小值或夹断频率。纯标准库、复用有界缓冲，未做实时优化或时间平滑。
- 契约：PitchDetection 的 pitches slice 长度为 0/1，不编造会话/时间戳；只有 Detected 携带估计，RMS 用去 DC 的相对满幅能量定义；confidence 仅为周期性。参数错误返回 Result，后续 worker 负责生命周期状态。
- 验证范围：22 个稳定纯音组合（44.1/48 kHz、27.5–1760 Hz 的 11 个离散频点）通过 ±1 cent，最坏约 0.053692 cent。19.9–5100 Hz 配置下，44.1 kHz/5000 Hz 原始误差 −1.319302299 cents，未达标；不宣称全频段精度。严格边界可能因插值偏差被拒绝，T07 应修复或明确范围限制，并保留 T06 作对照。
- 影响：不是实际麦克风或 UI 已可调音；直接 O(W×lag) 仅作参考，T07 负责泛音/噪声/衰减、边界及 CPU 预算。没有提前创建 trait/设备线程/FFT 架构，未来 worker 用实际 detector 后再决定抽象。
- 依据与接口细节见 TUNING_CORE，实测误差 CSV 和测试记录见 TESTING；未复制第三方算法代码。

## D018 — 架构重构与开发计划升级至 v2.0（2026-11-27）

- 决策：保留根目录原始冻结计划书不动（延续 D002），将 `docs/UNIVERSAL_TUNER_DEVELOPMENT_PLAN.md` 正式修订为 v2.0；把原 T08–T25 水平碎片路线重组为 P1–P8 垂直闭环阶段；确立四层架构（`tuner-core` → `audio-io`/`audio-decode` → `tuner-engine` → 极薄 `src-tauri` + React/Canvas UI）；推翻现有时域 `yin.rs` 内核并升级为 DSP 2.0（FFT 加速 Fast YIN + 双尺度窗口 + 谐波辅助 + 对数域 `PitchTracker` + 复用 `SpectrumAnalyzer`）；将 Windows WASAPI Loopback（系统声音内录）纳入 MVP 可选输入源。
- 原因：T00–T07 完成后仍未打通任何真实音频或文件链路；本机当前无麦克风（D015），若按原顺序先做 T09–T13 将受限于无设备验收；时域 YIN 早停在噪声下会退化回 $O(W \cdot L)$ 且 300 ms 单一窗口导致中高音手感粘滞；缺乏独立应用编排层会导致 `src-tauri` 膨胀；静态 JSON Demo 维护成本过高且不验证真实算法。
- 替代方案：严格按原 v1.0 T08–T25 顺序继续推进；因结构性返工风险高、端到端验证过晚而被用户否决，本轮已获用户明确批准执行 v2.0 方案。
- 影响：
  - `tuner-core` 新增 `rustfft` 与 `serde` 依赖，保留原 T06/T07 的 640 帧合成夹具作为强回归门槛，移除生产公共 API 中的 `detect_reference`。
  - 文件解码与离线分析提前至 P2，使真实乐器录音可尽早校准 DSP，并可作为 P3 虚拟实时流源端到端验证实时管线。
  - 后续停止向 Git 提交几十张重复 UI 截图，聚焦自动化测试、回归夹具与少量关键里程碑证据。
- 验证：P1 完成后通过全部 640 帧回归、频谱测试、PitchTracker 与性能基准，并同步更新 STATUS/HANDOFF/TESTING。
